# R3 本机客户端与工程验收实施说明

> 权威级别：L2（本轮范围、实施决定和验收门槛）
> 状态：本机与远程 CI 验收完成；跨机器延期
> 最后更新：2026-10-07

## 范围与验收

用户要求独立完成R3，已明确跨实体机器验收延后。本轮完成本机真实Unity客户端、GM与后端联调，以及归档、资源配额、监控、GitHub Actions远程CI、本机负载/持续运行和备份恢复。远程CI最终提交为 `e286589`，三个job全部通过；跨机器保留延期项。默认legacy及既有历史保留，R4退役和R5游戏服不纳入本轮。

实施顺序：

1. 安全归档：终态/全员结算/无待处理工作时形成摘要，压缩过期事件正文、已发布通知和可恢复的旧命令响应；保留原事件指纹/来源代次/序号、参与者结果、资产账本、奖励业务键和修复审计。默认关闭，保留天数和批次可配置，先在隔离数据验证。旧命令已归档时返回明确恢复指引，不重新执行。
2. 资源与监控：限制全局和来源IP的WS数量，保留原连接替换语义；验证慢客户端不会阻塞Worker。独立指标监听只提供指标，使用独立服务凭据，不复用游戏事件token；Prometheus/Grafana仅在本机测试网络暴露。
3. Unity：补请求关联、超时、连接代次与活动恢复；固化可生成的最小场景/Windows构建入口。独立工程副本构建并执行四个真实Unity进程，临时账号凭据只通过各自进程环境传入，客户端不能提交可信战斗事件或奖励金额。
4. GM：真实后端分页/刷新、身份失效、待修复原因及operator受控重试；沿用当前角色、稳定业务键、尝试版本和审计，前端不加币、不删除奖励依据。用真实浏览器验证。
5. 工程验证：编号迁移、完整回归/race、依赖支持与审计、重复构建、备份恢复与回滚演练；配置化本机负载和持续运行，记录实际机器、参数、时长和失败率，不外推商业容量。

## 约束和风险

- 归档不能改变仍运行的Run或待结算结果；压缩正文后重复事件仍需识别内容冲突，原奖励仍只能发一次。保留小型去重记录意味着存储不会无限期保持固定大小。
- 不清理原开发库进行测试。新迁移先在隔离环境及恢复副本验证；只有实际迁移完成的目标才记录schema更新。
- 服务事件凭据、指标凭据、玩家JWT和管理员JWT分别使用；凭据不进入仓库、命令行或测试输出。
- Unity已有Editor窗口与本机许可证由用户持有；编译/验证副本使用D盘临时和包缓存。不得绕过账号授权或此前被拒绝的C盘删除。
- 新接口/错误和存储行为在验证后同步L1契约、测试、部署/恢复说明及发布记录。实施说明不替代完成证据。

## 本机完成门槛

- 四个Windows Unity进程使用实际HTTP密码登录、Authorization头WS、房间/候选/任务/结果和重连恢复，输出脱敏结果。
- GM能看真实记录，普通GM不能修复，operator的明确重试只触发一次合法处理，错误、分页和过期身份均可解释。
- 摘要/正文压缩与并发/重复处理、配额/慢客户端、指标身份及告警均通过实际测试。
- 有可重复执行的CI命令、本机持续运行数据、恢复副本对账和回滚证据。未执行的平台或网络项列为延期，不填PASS。
