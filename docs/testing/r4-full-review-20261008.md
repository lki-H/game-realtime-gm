## 1. 范围和边界

复核当前源工作区：Go 认证/权限、HTTP/WS、Party/招募/匹配/Run/任务/结算、Worker/投影/归档、维护/排空/旧缓存退役、编号迁移、React GM/PVE 网页、Unity 控制面契约、Compose/回滚脚本及当前技术文档。

复核保留开发数据、备份和学习历史，不实施R5。跨机器、真实战斗模拟和共享生产部署继续延期。本轮对Unity做代码/契约核对，未重新运行Editor或Windows Player；发布验证单列于 [R4发布记录](r4-release-acceptance.md)。

## 2. 发现并修复的问题

| 问题 | 复现或证据 | 修复 |
| --- | --- | --- |
| 旧战绩 DATETIME 随V2 UTC连接被解释错，偏移8小时 | 合成 legacy `2026-08-23 10:48:12.123` 在修复前返回10:48Z；回归明确失败 | 只在 legacy 战绩/GM历史结算读取边界恢复Asia/Shanghai语义，不修改旧数据库行；修复后等价02:48Z |
| 结算修复进入事务前检查角色，等待操作锁时降级仍成功 | 阻塞 pending 行，降级operator后释放，修复前HTTP200 | 在 pending 行锁后以同事务管理员共享锁复核角色；修复后403，操作仍needs_repair |
| 并发重复修复的回执检查未由目标操作锁串行保护 | 补充两请求同时阻塞同一操作的回归 | 先锁目标再读稳定回执，两个请求均200且只产生一条审计 |
| 数据库排他锁持有连接丢失后进程仍可能运行 | 缺少运行期锁归属复核；增加释放锁夹具 | 每秒复核`IS_USED_LOCK`和连接身份，失败通知服务退出；不是多实例fencing承诺 |
| 超过100个活跃Run时维护循环反复处理最早100个 | 创建101个Run，修复前末尾Run经过两轮仍未更新 | 按`updated_at,id`轮转，保持批量上限并避免后续Run饥饿 |
| pprof启用时可配置公网监听；事件/指标凭据可误用JWT密钥 | 启动配置检查缺失 | pprof只接受显式loopback IP；事件和指标启动拒绝复用JWT密钥 |
| 两个网页默认后端端口不同，localhost访问PVE时WS代理拒绝 | Vite配置分别8080/18082，WS只允许127.0.0.1 | 默认均8080，均支持本机`PVE_BACKEND_URL`；PVE仅额外允许localhost:5174，同源限制保留 |
| 玩家身份失效后界面仍保留已登录状态；迟到HTTP响应可能影响新会话 | 控制面HTTP403/旧token响应恢复路径不完整 | 401/40321关闭玩家会话并回登录页；响应解析前后复核当前token，忽略旧响应 |
| 明确拒绝的重试意图仍可能显示为结果未知 | `lastUnknown`只在成功回执清空 | 同意图收到明确结果时清空未知状态；浏览器模拟已验证 |
| GM请求完成回调可能污染新登录状态 | 异步catch/finally缺少当前token比较 | 回调复核token；管理员失效仍显示重登原因 |
| 迁移说明、旧实时观察契约、交接入口与R4事实不一致 | 仍写stage r2/r3、没有维护API、R4未开始 | 更新day40运行入口、legacy-only观察路径、50371与本机R4当前状态；旧日期化记录保留 |
| 回滚测试用当前测试进程执行重放，未充分验证实际旧进程 | 原测试启动R3但重放由当前fixture调用 | 通过实际R3/R4独立内部HTTP入口重放，恢复pending由各自Worker执行 |
| 回滚验证脚本清理失败只警告，可能报告成功 | `down -v`失败分支没有失败退出 | 清理失败使脚本失败，同时恢复原环境变量 |

## 3. 已运行验证

- 普通 Go 全量测试、`go vet ./...`、Go格式检查通过；API/OpenAPI引用测试通过。
- 专用 `gm-r4-audit`、MySQL8.4.11/RedisDB14：新增失败回归在修复前按正确期望失败，修复后全部通过。
- 全量 `backend/tests/v2` 通过，耗时122.533秒；Linux Go1.27.1真实MySQL/Redis `-race` 通过，耗时92.723秒。使用隔离库，不以普通测试中的SKIP冒充存储验证。
- 实际R3/R4二进制：有奖励四人Run，查询/旧finish拒绝/重复事件经独立HTTP/实际Worker恢复均通过，奖励总额495、发奖7条、账本算术错误0。
- 两个React项目TypeScript检查/生产构建通过；npm官方registry生产依赖审计均为0漏洞。
- Chrome DevTools：GM真实登录、观察、管理员删除后的失效提示；正常流程无应用控制台错误。撤销身份测试中的403网络错误为预期拒绝。
- Playwright：PVE真实登录、WS、建房、封禁后退出、localhost代理；另验证迟到403不能替换新会话、明确拒绝清除未知意图。
- PowerShell回滚脚本语法和修改文档空白检查通过；未将修改后的完整回滚脚本执行或未运行的Unity联调记为通过。
- 临时Go、双Vite、浏览器测试页面、`gm-r4-audit` 容器/网络/测试卷和两个回滚二进制已清理；原开发MySQL/Redis保持停止，Docker Desktop恢复停止。开发库、原数据卷和备份保留。

## 4. 剩余限制

最后一轮在上述范围内未发现新的可复现故障，不代表数学上保证不存在任何缺陷。跨机器、Unity本轮重构建、共享环境长期观察/容量、真实战斗服和R5不属于本轮通过项。

冻结的旧战绩时间语义已修复。共用玩家/管理员/审计表可能存在不同时期写入时间，缺少逐行来源标记；无法安全推断旧行，不能批量加减8小时。当前文档明确该历史边界，后续若需统一迁移须另行以真实备份核对。

复核没有修改已应用迁移、开发数据库或依赖版本。旧远程R3 CI证据只属于R3；当前R4发布验证和版本基线见 [R4发布记录](r4-release-acceptance.md)。
