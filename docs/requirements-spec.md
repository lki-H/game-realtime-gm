# 工作实战版需求分析

## 需求原则

后端核心仍是工作实战主线。GM 后台和游戏 Demo 只展示和验证后端能力，不反向定义后端需求。

## 后端核心需求

- 玩家注册、登录、JWT 鉴权。
- 管理员登录和管理员鉴权。
- 玩家查询、昵称修改、封禁和解封。
- GM 操作日志。
- Redis 在线状态。
- WebSocket 长连接、心跳、连接管理。
- 小队房间：创建、加入、离开、准备、状态广播。
- PVE 任务匹配、任务副本、结算、排行榜。
- 测试、压测、文档和演示脚本。

## GM 后台需求

V1：

- 登录。
- Dashboard。
- 玩家管理。
- 封禁和解封。
- 操作日志。
- 危险操作二次确认。

V2：

- 在线状态观察。
- 小队、匹配、任务、结算、排行榜观察。

## 游戏 Demo 需求

V1：

- 玩家登录。
- WebSocket 建连。
- 创建小队、加入小队、离开小队、ready。
- 小队状态展示。

V2：

- 任务开始、任务状态、任务完成、结算和排行榜。

V3：

- Phaser 小地图。
- 位置同步。
- 观战视角。

## 非功能需求

- 接口错误可解释。
- 危险操作可审计。
- 演示数据可重置。
- 文档能区分已实现、规划中和当前不做。
- 前端 token 存储仅作为本地学习方案。

## 当前不做

- 完整游戏客户端。
- 复杂战斗系统。
- 微服务拆分。
- KCP、QUIC、自研 TCP。
- 复杂 RBAC 和运营活动系统。
