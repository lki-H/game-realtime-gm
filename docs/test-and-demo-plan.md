# 测试与演示方案

## 验证目标

项目要从“能跑”变成“能稳定演示、能复盘、能面试讲清楚”。

## 后端检查

- `go test ./...` 编译和测试。
- 后续在支持 cgo 和 gcc 的环境运行 `go test -race ./...`。
- 用 Apifox 或 curl 验证 HTTP API。
- 用 Apifox WebSocket 或 Demo 验证实时消息。
- 用 PostgreSQL 检查长期数据。
- 用 Redis 检查在线状态、匹配队列、排行榜。

## GM 后台冒烟测试

- 管理员登录成功。
- token 失效后回到登录页。
- Dashboard 正常加载。
- 玩家列表可分页。
- 玩家搜索可用。
- 玩家详情可打开。
- 封禁和解封有二次确认。
- 操作日志能看到记录。
- 接口失败能显示错误提示。

## 游戏 Demo 冒烟测试

- 玩家登录成功。
- WebSocket 连接成功。
- 能看到 `connection_id`。
- 能创建小队。
- 能加入小队。
- 能离开小队。
- 能切换 ready。
- 能看到最近 WebSocket 消息。
- 错误消息可见。

## 失败场景

- 未登录连接 WebSocket。
- 管理员 token 连接玩家 WebSocket。
- 重复创建小队。
- 加入不存在小队。
- 小队满员。
- 未 ready 开始任务。
- 重复结算。
- 被封禁玩家登录失败。

## 危险操作检查

每次新增危险操作，必须确认：

```text
前端二次确认
后端权限校验
GM 操作日志记录
```

## 演示验收

录屏或面试演示前必须完整跑一遍：

```text
Docker -> 后端 -> GM 后台 -> Demo -> 小队/任务/结算 -> GM 观察
```

## 当前不做

- 不依赖偶然数据演示。
- 不只展示成功流程。
- 不用前端演示替代后端测试。
