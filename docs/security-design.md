# 当前安全设计与信任边界

本仓库支持个人本机与隔离测试，不开放公网，不保存真实付费资产。本说明覆盖当前V2、历史legacy限制、R5和本机工具；旧风险台账保留在Git基线401247d及历史复核报告，不用已解决的旧风险定义当前代码。

## 边界与资产

不可信玩家经HTTP／WS进入Go；管理员也必须逐请求鉴权；受控局内Bot使用独立本机服务身份。MySQL保存账号、权限、奖励、账本和事实；Redis是投影。主机或服务密钥被控制不在客户端防作弊保证范围。

## 当前控制

| 范围 | 控制与边界 |
| --- | --- |
| JWT／注册 | 固定签名方法、期限必需；注册在bcrypt前检查UTF-8字节上限；哈希和令牌不输出 |
| 玩家与管理员 | subject分离；V2玩家会话代次、封禁及期限复核；管理员会话读取当前状态 |
| operator修复 | 指定维修入口实时复核operator、目标和指纹，事务写审计；不宣称全站细粒度RBAC |
| HTTP／WS | 期限、body／header、消息和连接预算；登录／注册与握手／命令限流；不信任任意转发头 |
| V2 Origin | 同源或无Origin的受控非浏览器客户端；本机Vite代理验证来源，不能称无条件允许 |
| 事实和资产 | 操作指纹、顺序水位、事务、唯一奖励来源和账本；查询可恢复通知丢失 |
| Worker | 明确任务分派与隔离；完成／失败按所选状态、次数和时间更新；不增加多实例写能力 |
| 诊断 | pprof默认关闭、显式loopback；测试事件和metrics凭据独立，公开日志不记录query令牌或正文 |
| 本机安装 | 隔离默认、仓库外随机凭据、严格路径／权限／资源归属；不重建已有卷“修复”认证 |
| R5 | 只读恢复视图、独立投递／报表与服务／MQ身份；v1严格消息、fingerprint、事务后ACK和有限重试 |

## 历史与残余风险

legacy是显式历史回归模式。其旧握手、进程内状态和演示入口仍按历史限制理解，不作为公网兼容承诺。普通GM的全部既有运营接口并未因新增operator维修规则自动具备细粒度RBAC。

本机明文HTTP／RPC只适用于已锁定的本机场景；私有地址不等于传输保密。公网前需另行设计TLS、短期连接凭据、入口预算、管理员保护、审计和密钥轮换。本次不通过关闭鉴权、放宽Origin或删除回归获得通过。

R5角色配置减少无关凭据和依赖，但同OS用户／管理员仍可访问其权限内文件；它不是进程沙箱。外置重投审计文件与SQL提交不原子，unknown结果必须核查，不能自动重试。不得给过期消息刷新时间或换ID来伪造成功。

新安装不用固定seed账号；原seed字节仅为历史初始化资料保留。旧Compose模板变为显式凭据与loopback，不自动应用到原容器。已有数据只能用原凭据，通过明确检查，不把测试fixture指向原库。

依赖与公开文件检查是维护机制，不是无漏洞保证。实际检查的来源、范围和结果见[维护记录](maintenance/README.md)，问题报告见[安全策略](../SECURITY.md)。
