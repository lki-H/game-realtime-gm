# 项目展示总入口

## 定位

本文是 `game-realtime-gm` 的展示总入口，用来串联后端主线、GM 后台、游戏 Demo 和求职展示。

本文只记录展示总路径和文档关系。具体演示步骤维护在 `docs/demo-plan.md`，不要在两处重复维护同一份流程细节。

核心原则：

```text
后端主线决定能力
        ↓
GM 后台把能力可视化
        ↓
游戏 Demo 验证玩家实时链路
```

## 展示目标

项目最终要证明的不是“做了一个完整游戏”，而是：

- Go 后端能完成玩家账号、鉴权、数据持久化、实时连接和运营管理闭环。
- Redis 和 PostgreSQL 能分别承担实时状态与长期可靠数据。
- WebSocket 能承载小队、任务、位置同步等实时业务。
- GM 后台能观察和审计玩家、小队、匹配、任务、结算、排行榜等状态。
- 轻量游戏 Demo 能稳定演示玩家侧行为，并让 GM 后台看到这些行为产生的数据变化。

## 展示层关系

GM 后台是后端能力的观察窗，负责观察、管理和审计。

游戏 Demo 是后端能力的验证器，负责验证玩家登录、WebSocket、小队、任务、位置同步、结算和排行榜链路。

两者都服务 Go 游戏服务端主线，不反向牵着后端乱跑。

## 优先级

```text
P0：完成 Day27-Day35 后端闭环
P1：补 ws-protocol、测试、seed、演示脚本
P2：做 GM 后台轻量版
P3：做游戏 Demo V1
P4：做 Phaser 移动同步和观战视角
P5：整理项目展示材料和面试表达
```

## 当前不做

- 不把项目包装成大型商业游戏服务器。
- 不为了前端页面效果新增脱离 PVE 主线的后端功能。
