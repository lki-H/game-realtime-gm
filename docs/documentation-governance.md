# 文档治理规范

> 文档角色：文档分层、冲突处理与维护规则
> 权威级别：L0（治理规则）
> 状态：已生效
> 适用范围：仓库内全部文档与公开发布材料
> 事实来源：当前代码、路由、数据库结构、测试记录与项目协作规则
> 最后更新：2026-08-31

## 1. 治理目标

本规范解决三个问题：当前事实从哪里查、同一内容由谁维护、哪些材料可以公开。项目不追求文档数量，而追求每类信息只有一个明确事实源。

## 2. 事实优先级

当文档与实现冲突时，按以下顺序判断：

1. 当前可运行代码、SQL、Docker Compose 和自动测试。
2. 当前机器契约：`openapi.yaml`。
3. 当前协议契约：`ws-protocol.md`。
4. 当前需求、HLD、LLD、数据库、安全、测试和运维文档。
5. ADR、阶段规划、展示规划和学习路线。
6. 非公开研究、历史学习、学术整理和内部协作材料。

发现 L1-L3 文档与代码不一致时，必须记录差异并修正文档；不能用旧文档反向证明代码已经实现某项能力。

## 4. 文档分类

| 分类 | 用途 | 是否可定义当前事实 | 默认公开 |
| --- | --- | --- | --- |
| 权威实战 | 当前需求、架构、契约、数据、安全、测试、运维 | 是 | 是 |
| 规划 | 尚未实现的前端、Demo、学习和优化事项 | 否 | 按文件判断 |
| ADR | 记录决策背景、取舍和状态 | 仅解释已接受决策 | 按文件判断 |
| 非公开研究 | 外部信号、行业资料、长期学习方向 | 否 | 否 |
| 历史学习 | 逐日学习过程 | 否 | 否 |
| 学术整理 | 学校表达版本 | 否 | 否 |
| 内部资料 | 上下文、交接和工具采用记录 | 否 | 否 |

## 5. 状态词

- `已实现`：代码存在，并完成与风险相匹配的验证。
- `实验验证`：在明确环境和参数下验证，不代表生产能力。
- `规划中`：尚未进入当前实现，不能使用完成时态。
- `当前不做`：明确排除在当前范围外。
- `历史记录`：保留学习过程，不参与当前事实判断。
- `非权威研究`：仅提供外部信号、推断或职业规划。

## 6. 活跃文档元信息

活跃文档顶部必须包含：

```markdown
> 文档角色：
> 权威级别：
> 状态：
> 适用范围：
> 事实来源：
> 最后更新：YYYY-MM-DD
```

历史学习和学术整理材料只增加分类说明，不改写其原始正文。

## 7. 契约维护

- 新增、删除或修改 HTTP 路由时，同步修改 `openapi.yaml`、`api-overview.md` 和需求追踪表。
- 修改 WebSocket 消息时，同步修改 `ws-protocol.md`；OpenAPI 不承载 WebSocket 业务消息。
- 修改表、索引或 Redis key 时，同步修改 `database-design.md`。
- 修改认证、权限、敏感日志或 Secret 处理时，同步修改 `security-design.md` 和相关测试。
- 每次发布更新 `release-notes.md`，只记录已经完成并验证的事实。

## 8. 公开发布边界

公开副本只同步 `public-index.md` 列出的权威实战材料。发布前必须检查：

- 不包含非公开研究、历史学习、学术整理或内部协作内容。
- 不包含本机绝对路径、旧私有提交标识、账号备忘、原始日志、profile 或备份文件。
- 不包含真实 JWT、GitHub token、线上密码、私钥或个人信息。
- 未来能力明确标记为规划或非目标。
- README 中的链接在公开副本内真实存在。

## 9. 变更流程

```text
核对代码与运行事实
-> 更新唯一权威源
-> 更新导航和必要的人类阅读指南
-> 校验路由、链接、Markdown、YAML 和敏感信息
-> 精确同步公开子集
-> 记录版本与工作日志
```

大规模重写不得回退用户未提交代码，也不得用历史或研究材料覆盖当前事实。
