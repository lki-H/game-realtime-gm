# 演示方案

> 文档角色：当前后端演示脚本与未来客户端验收
> 权威级别：L3（演示规划）
> 状态：后端、React与Unity Windows控制面已实现并本机验证；跨机器延期
> 适用范围：面试、录屏和阶段验收
> 事实来源：当前 API/WS 契约、测试计划与前端规划
> 最后更新：2026-10-10

## 1. 当前可执行演示

使用 Apifox/curl、WebSocket 客户端或 `ws_bot`：

1. 启动 Docker MySQL/Redis 和 Go 服务。
2. `GET /health`，记录响应 `X-Request-ID`。
3. 两名玩家登录并建立 WebSocket，确认 welcome。
4. 创建/加入小队、ready，观察直接响应和另一成员广播。
5. 创建任务，执行 ready/start/finish。
6. 提交结算，再使用同请求重试，证明余额/流水不重复。
7. 查询排行榜、个人排名和战绩。
8. 管理员查询实时摘要、玩家观察和结算。
9. 封禁/解封玩家，检查操作日志和重复操作错误。
10. 用 MySQL/Redis CLI 对照事实与投影。

## 2. 必演失败场景

- 玩家/管理员 token 混用。
- 加入不存在或已满小队。
- 非队长迁移任务，或未全员 ready 时启动。
- 匹配重复排队/超时。
- 任务未 finished、nonce 重放或 key 冲突的结算。
- 重复封禁或解封未封禁玩家。

## 3. 演示数据

- 使用固定前缀的本地测试账号和任务 ID，便于清理。
- 演示前记录初始余额、结算数和排行榜；演示后对照增量。
- 不使用真实个人信息、真实密码或生产数据。
- seed 和清理规则见 [演示数据方案](data-seed-plan.md)。

## 4. 未来 GM 后台验收

- 登录、Dashboard、玩家查询、封禁/解封二次确认、审计筛选。
- 实时摘要、玩家观察、结算和榜单。
- loading/empty/error/token 失效均有明确状态。
- 展示 request ID 与 observed_at，不把前端轮询称为实时全服监控。

## 5. 未来 Unity Demo 验收

- V1：登录、建连、welcome、小队、ready、广播和重连查询。
- V2：任务生命周期、幂等结算、榜单和战绩。
- V3：轻量 3D 场景与客户端性能/弱网观察；新增位置能力前先更新真实协议。

## 6. 录屏与截图

- 开场：README、架构图和能力边界。
- 主体：成功闭环 + 一个鉴权失败 + 一个幂等重试。
- 证据：MySQL 事务结果、Redis key、测试命令和性能基线摘要。
- 结尾：明确单实例、内存状态、无真实撮合/前端/云部署等限制。

录制前清理 token、密码、绝对路径、账号备忘、原始日志/profile 和私人材料。
