# 演示方案

## 演示定位

游戏 Demo 是后端能力的验证器，不做完整游戏。它只验证玩家登录、WebSocket、小队、任务、位置同步、结算和排行榜链路。

GM 后台是后端能力的观察窗，用来观察 Demo 产生的在线状态、小队状态、任务状态、结算记录、排行榜和操作日志。

## 主演示流程

```text
1. 启动 Docker PostgreSQL 和 Redis
2. 启动 Go 后端
3. 启动 GM 后台
4. 启动游戏 Demo
5. GM 管理员登录
6. 两到四个玩家登录 Demo
7. 玩家 1 创建小队
8. 其他玩家加入小队
9. 成员切换 ready
10. 队长开始任务
11. 玩家完成轻量任务目标
12. 任务结算
13. 排行榜变化
14. GM 后台查看在线、小队、任务、结算、日志、排行榜
```

## 成功场景

- 玩家登录成功并拿到玩家 token。
- WebSocket 连接成功并收到 `server.welcome`。
- 创建小队后返回小队 ID。
- 其他玩家加入后，小队状态更新。
- ready 状态变化后所有成员能看到状态。
- 任务开始后进入任务状态。
- 任务完成后产生结算记录。
- 排行榜更新。
- GM 后台能观察到上述状态变化。

## 失败场景

- 未登录连接 WebSocket。
- 管理员 token 连接玩家 WebSocket。
- 重复创建小队。
- 加入不存在的小队。
- 小队满员。
- 未 ready 不能开始任务。
- 重复结算被拒绝或返回已有结果。
- 被封禁玩家不能登录或连接被断开。

失败场景用于展示后端严谨性，不是为了让 Demo 变复杂。

## 多账号演示

准备 `player01` 到 `player04` 测试账号。Demo 登录页提供快速填充或快速登录入口。

建议支持：

- 当前账号标签。
- 清空本地 token。
- 退出当前玩家。
- 多窗口打开提示。

## 观战视角

后期可以增加只读观察页：

```text
/observer/mission/:id
```

观战视角不控制玩家，只展示任务内玩家位置、任务状态和结算结果。它可以和 GM 后台的任务观察页互相印证。
