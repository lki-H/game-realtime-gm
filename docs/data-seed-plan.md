# 演示数据与 Seed 方案

## 目标

GM 后台和游戏 Demo 不能依赖偶然产生的数据。演示前应能稳定准备测试管理员、测试玩家、封禁玩家、小队、任务、结算和排行榜数据。

## 数据类型

### 测试管理员

- `admin`：本地超级管理员，用于登录 GM 后台。
- 后续可补 `gm01`：普通 GM，用于演示权限差异。

### 测试玩家

- `player01`
- `player02`
- `player03`
- `player04`

用于多窗口创建小队、加入小队、ready 和任务演示。

### 封禁玩家

- `banned01`

用于演示被封禁玩家不能登录、GM 操作日志和玩家状态筛选。

### 小队数据

当前小队仍以内存状态为主，演示时优先通过 Demo 实时创建，不提前伪造。

### 任务与结算数据

Day28-Day35 后根据实际表结构补充：

- 任务模板。
- 任务副本。
- 任务参与者。
- 结算记录。
- 奖励记录。
- 排行榜数据。

## 重置原则

- 本地演示数据应可重复执行。
- 管理员 seed 不应写入真实强密码。
- seed 不应覆盖用户真实数据，除非明确使用本地演示数据库。
- Redis 临时 key 应提供清理说明。

## 文档归属

具体 SQL 或 seed 工具后续可放在：


## 当前不做

- 不在当前阶段生成大量假数据。
- 不把演示 seed 当成生产初始化方案。
- 不提交真实手机号、邮箱、数据库密码或 JWT secret。
