# 0004：GM 后台先做轻量版

## 背景

GM 后台能提升项目展示效果，但项目核心仍是 Go 后端闭环。

## 决策

GM 后台先做轻量版，优先覆盖登录、Dashboard、玩家管理、封禁解封和操作日志。

## 原因

- 当前后端已有对应接口，能快速页面化。
- 轻量后台足以证明玩家管理、权限隔离和审计能力。
- 复杂后台会消耗过多时间，影响后端主线。

## 暂不采用

- 复杂 RBAC。
- 菜单动态配置。
- 低代码后台。
- 公告、充值、活动、多租户、多大区管理。

## 影响

GM 后台 V2 再接入在线状态、小队、匹配、任务、结算和排行榜观察。没有后端审计的危险操作，前端先不做。
