# 0001：保持单体架构

## 背景

项目当前目标是训练 Go 后端工程能力，并完成账号、GM、在线状态、WebSocket、小队、匹配、任务、结算和排行榜闭环。

## 决策

当前阶段保持单体 Gin 服务。

## 原因

- 单体服务更容易本地启动、调试和演示。
- 初学阶段更容易讲清楚请求链路和数据流。
- Day27-Day35 的重点是业务闭环，不是部署架构。
- 没有压测数据前，过早拆分微服务容易变成堆名词。

## 暂不采用

- 微服务拆分。
- 网关 + 多逻辑节点。
- Kubernetes/Agones 调度。
- 多进程跨节点广播。

## 影响

后续 GM 后台和游戏 Demo 只接入当前单体后端暴露的 HTTP API 和 WebSocket，不为了展示层提前拆分后端。
